这是一篇只用于本地检查的草稿文章。它集中展示网站支持的 Markdown 元素，帮助我们判断不同文章是否仍然属于同一套安静、克制的阅读系统。

正文的目标不是制造“设计感”，而是让结构自然浮现：标题负责分层，段落负责论述，引用负责保留他人的话，提示块只处理真正重要的补充。

## 改变不是一个动作，而是一种关系

线性思维会寻找一个明确原因：是谁做错了，哪一步出了问题，应该怎样纠正。循环思维则把注意力放在关系之中，观察一个人的反应如何成为另一个人下一次反应的条件。

这并不是取消责任，而是把责任放回真实的互动结构中。只有看见结构，我们才可能找到新的入口。

> 问题并不只存在于一个人身上，它也存在于人与人之间不断重复的回应里。

### 从线性问题转向循环问题

一个简洁的练习，是把“为什么”改写成“当……发生时，接下来发生了什么”。问题从追究原因，变成观察顺序。

1. 描述一个具体场景，而不是概括一个人的性格。
2. 记录每个人先后做了什么。
3. 寻找哪一个微小变化可能打断循环。

{{< callout type="key-point" >}}
提示块只保留真正影响理解或行动的信息。它不是装饰，也不替代普通标题。
{{< /callout >}}

#### 一个判断原则

如果一句话离开底色或粗体之后仍然重要，它才值得被强调。其余内容应继续安静地留在正文里。

## 不同内容应该使用不同结构

| 内容类型 | 主要结构 | 适合使用 |
| --- | --- | --- |
| 长文／随笔 | 开场、章节、转折 | H2、H3、引用 |
| 读书笔记 | 原文、理解、连接 | 引用、脚注、图片 |
| 方法／指南 | 目标、步骤、判断 | 列表、提示、代码 |

行内代码只用于短命令或字段，例如 `title`。多行内容使用独立代码块：

```md
## 主要章节

### 次级主题

正文只负责表达，样式由网站统一管理。
```

{{< callout type="note" >}}
补充说明保持中性，不与正文争夺注意力。
{{< /callout >}}

{{< callout type="warning" >}}
不要用提示块包装普通段落，也不要恢复自动目录。
{{< /callout >}}

---

最终的规则应该让作者不再需要思考字号、颜色和间距，只需要判断这段内容究竟是标题、正文、引用、列表还是说明。[^1]

[^1]: 脚注用于来源和必要补充，不承担正文中的主要论证。
